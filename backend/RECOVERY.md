# BID OWL P2-19 — 백업 무결성 확인 및 새 파일 복구

이 기능은 **기존 고객 SQLite를 삭제하거나 덮어쓰지 않는 복구**를 구현합니다. 기존 운영 DB에 대한 자동 원위치 복원은 아직 지원하지 않습니다. 모든 검증과 복사는 Windows PC 내부에서 실행되도록 설계했으며 외부 서버, API 키, AI, PDF 패키지가 필요하지 않습니다.

## 원칙

- **기본은 검증/미리보기만** 수행합니다. 소스 SQLite를 읽기 전용(`mode=ro`)으로 열며 복원 경로·상위 폴더를 만들지 않습니다.
- `--apply`를 지정한 경우에만 운영 DB와 별도의 **새 경로**에 복구합니다. 복구 경로가 이미 있거나 백업 파일과 같으면 실패합니다. 기존 운영 DB나 기존 백업을 자동 교체/삭제/활성화하지 않습니다.
- 복원 전: BID OWL v1 `PRAGMA user_version=1`, 7개 필수 테이블, **전체 `integrity_check`**, `foreign_key_check`, 주요 데이터 건수, SHA-256 바이트 체크섬과 파일 식별 정보를 확인합니다.
- 복원 시: 미리보기와 파일 식별값·SHA-256이 동일한지 재확인하고 대상 파일을 `open("xb")`로 배타적으로 새로 만든 뒤, SQLite 온라인 `backup()` API를 사용합니다. 데이터는 신규 파일에서 무결성·테이블·건수를 다시 검사합니다.
- 파일이 미리보기 후 바뀌거나 오류가 나면 적용을 중단합니다. 자신이 배타 예약한 신규 파일만 삭제를 시도하며 다른 프로세스 파일을 지우지 않습니다.
- 엔진 지문이 없는 기존 v1 DB도 유효한 백업이면 새 파일로 복원할 수 있습니다. 하지만 과거의 `PASS`는 현 엔진 판정으로 신뢰하지 않고 조회 화면에서 `UNKNOWN`으로 남습니다.

## 개발자 CLI

```powershell
cd backend

# 1. 백업 내용 검사만 (DB나 복원 디렉터리 생성 안 함)
python backup_recovery.py --source "C:\data\backups\bidowl_snapshot.sqlite3" --destination "C:\data\recovered\bidowl_new.sqlite3"

# 2. 요약·경로를 확인하고 새 파일로 복구하기로 명시적으로 결정한 경우
python backup_recovery.py --source "C:\data\backups\bidowl_snapshot.sqlite3" --destination "C:\data\recovered\bidowl_new.sqlite3" --apply
```

반환 값은 `RECOVERY_PREVIEW_NO_WRITE`, `RESTORED_TO_NEW_FILE`, `RECOVERY_FAILED` 중 하나입니다. `record_counts`에는 공고·회사·판정·가져오기 수가, `source_sha256`에는 백업 바이트 체크섬이 담깁니다.

복원에 성공해도 자동으로 현재 사용 중인 DB를 바꾸지 않습니다. 앱/뷰어를 종료한 뒤, 사용자가 **새 경로를 명시적으로 선택**해서 검사하고 사용해야 합니다. 원래 DB 파일은 별도로 보관하고 외부에서 강제 덮어쓰기·자동 원상복구하지 마세요.

## 위험과 제한

- 실제 **고객 데이터**가 들어있는 파일을 GitHub에 업로드하거나 실사용 테스트에 사용하지 않습니다. 테스트는 합성 데이터와 OS 임시 경로에 한정합니다.
- WAL(`-wal`) 또는 롤백 저널(`-journal`) 파일이 보이면 복원용 백업으로 받지 않습니다. 먼저 원본 앱을 종료하고 SQLite 공식 백업 기능으로 **일관된 스냅샷**을 생성해야 합니다. 단순 파일 복사는 누락된 WAL 트랜잭션이 있을 수 있습니다.
- 파일이 바뀌는 동시성·네트워크 스토리지·OneDrive 동기화·inode 재사용을 완전히 막는 OS 락은 아닙니다. 운영 앱 정지 후 로컬 드라이브에서 수행해야 합니다.
- 소스 백업이 데이터베이스 구조나 파일 무결성을 통과하더라도 **비즈니스 규칙 및 공고 원문 정확성**까지 보증하지 않습니다.
- 파일 접근 권한/디스크 공간/안티바이러스 잠금으로 복원이 실패할 수 있습니다. 중단 후 생성된 출력 파일 또는 sidecar가 남았는지 확인하고 새 경로로 재시도해야 할 수 있습니다.
- Windows 표준 UI, 단일 EXE 설치·운영 DB 자동 전환, 자동 복원 시 롤백 보장은 이 범위에 포함하지 않습니다. **프론트엔드 디자인은 사용자 지시로 보류**합니다.

## 검증 경계

`tests/test_backup_recovery.py`에 합성 DB용 14개 테스트 함수가 정의되어 있습니다. 독립 Python/sqlite3 임시 DB 계약 시험은 **8/8 PASS** (읽기 전용 원본 구조 확인·무결성·FK 검사·새 파일 복사·원본 보존·복구 내용·덮어쓰기 거부·누락 파일 비생성). 이것은 실제 비공개 GitHub 모듈과 Windows 전체 Python 테스트 PASS를 뜻하지 않습니다. Windows 연결 핸들 잠금, 폰트·Excel·PDF 및 본 개발 브랜치 전체 테스트 실행은 여전히 출시 전 검증 대상입니다.
