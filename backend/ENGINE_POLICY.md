# BID OWL — P2-16 규칙 엔진 버전·판정 무효화 계약

이 문서는 현재 개발 브랜치의 **구현 설계와 검증 한계**를 기술합니다. 상용 검증 완료 확인서가 아닙니다.

## 판정의 현재성 조건

로컬 Viewer에서 판정이 현재 유효(PASS/FAIL/UNKNOWN)하게 표시되려면 다음을 모두 만족해야 합니다.

1. 현재 공고 버전과 저장된 평가의 공고 버전이 같음
2. 현재 회사 프로필 버전과 저장된 평가의 프로필 버전이 같음
3. 저장된 평가에 **확인 가능한 규칙 엔진 SHA-256 지문**이 있으며 현 실행 코드와 일치함
4. 로컬 등록기로 재사용할 때는 저장된 마감 여부와 현재 마감 여부도 일치해야 함

하나라도 확인할 수 없으면 화면에서 현재 상태를 `UNKNOWN`, `requires_human_review=true`로 표시합니다. 과거 원본 판정은 `snapshot_status`로 남겨 보고서에 보존하지만 **오늘의 PASS를 의미하지 않습니다**.

## 지문 구성

`bidowl/engine_identity.py`는 `eligibility.py`(조건 비교), `schema.py`(Bid·마감), `profile.py`(회사 정보), `store.py`(판정 저장 경로)의 **로컬 소스 파일 바이트**와 파일명/길이를 구분하여 SHA-256으로 해시합니다. 이는 프로그램 소스 변경 탐지용으로 고객 파일, 평가 데이터, 사용자 비밀값을 해시하지 않습니다.

지문이 없는 평가 또는 다른 지문으로 평가된 공고는 다시 가져올 때 재평가합니다. 최신 버전의 `BidOwlStore.assess_and_record`는 평가/세부 근거/엔진 지문을 **같은 SQLite 트랜잭션**으로 저장하여 지문 기록 실패 시 해당 평가도 롤백합니다.

## DB v1 추가 메타데이터와 백업

새 DB에는 `assessment_engine_provenance(assessment_id PRIMARY KEY, engine_hash TEXT)` 테이블을 초기화 단계부터 포함합니다. `PRAGMA user_version`는 기존 v1을 유지하며 평가 기록의 구조/내용을 덮어쓰지 않습니다.

**기존 DB에는 읽거나 미리보기만 할 때 테이블을 추가하지 않습니다.** 저장 명령 `import_local.py --apply` 또는 `profile_workflow.py --apply`에서 기존 DB의 **덮어쓰지 않는 백업이 성공한 다음** 필요한 경우 테이블을 추가합니다. 오래된 평가에는 소급해서 현재 지문을 찍지 않습니다. 후속 새 평가에만 지문을 남깁니다.

다른 구형 쓰기 경로(`cli.py` 등)가 메타 테이블 없는 오래된 DB에 평가만 추가할 수 있습니다. 그러한 평가도 현 코드 지문이 입증되지 않아 조회 화면에서는 UNKNOWN으로 처리됩니다. 해당 DB는 새 등록기를 이용해 백업·재평가해야 합니다. 이는 안전한 보수적 동작이며 구형 경로 정비는 별도 작업입니다.

## 예외·환경

지문 확인에 필요한 코드 소스 파일이 설치 패키지에서 누락되면 `import_local.py`는 저장 전에 실패합니다. Viewer는 읽기 전용 접근을 유지하되 이전 판정을 UNKNOWN으로 표시합니다. 단일 EXE 패키징에서는 소스 포함 또는 별도 검증된 정적 매니페스트가 필요합니다. 로컬 DB를 임의로 조작하는 사용자를 막는 서명·인증 기능은 아닙니다.

필수 검증 게이트: 189개 전체 Python 테스트 실제 실행, 구형 DB 백업/마이그레이션 및 Windows 잠금 회귀, 7테마 UI, 데이터 정확성, 한글 PDF·Excel, Windows 인스톨러와 복구 테스트. 현재 구현된 테스트 정의를 실행 결과로 표기하지 않습니다.
